# dsv4-flash0731 / 4×RTX PRO 6000 PCIe 研究路线

## 研究问题

在固定权重、四卡资源和可比较负载下，分别优化低并发延迟与高并发吞吐；识别容量、通信、SM120 内核及调度限制。不将 GB300/NVLink 配方直接当作本机结论。

## 阶段和筛选规则

1. 静态调查：config、权重头部、vLLM 已安装源码、驱动/PCIe/NUMA。区分模型数学结构与框架实际切分。
2. 通信基线：限定 GPU 0–3，有界测试 all-reduce、all-gather、all-to-all 和 GPU 对拷贝，覆盖小 token 激活与批量激活；报告延迟与有效带宽，不能直接代替模型性能。
3. 基础可行性：先使用保守上下文/批量与明确 SM120 backend；检查加载、推理输出、设备显存、告警。失败按配置/内核/容量/通信分类，保留日志。
4. 方案筛选：TP4；TP4+EP；Attention DP4+EP4；TP2×DP2+EP4；TP2×PP2；PP4；TP2 两副本（显式 independent DP），必要时 PP2 两副本。单卡仅评估容量及 offload/进一步量化的代价，不把原格式不可容纳说成所有单卡方案不可能。
5. 性能比较：可行方案共用模型、生成设置、固定种子/输入、实际生成 token 数和计时口径。短输入低并发、长输入低并发、短输入高并发分别比较。先筛选，再对候选做重复测量和更细并发扫描。
6. 专项：DSpark 可用性与实际收益（接受率/输出一致性约束）；Attention/MoE 同卡不同分片与异卡分离分别分类；通信 backend、CUDA graph/eager、prefill chunking 按瓶颈证据决定是否实验。
7. 交付：原始结果、精确命令/环境、失败记录、工作负载定义、条件化推荐和局限。无性能数据的方案不得进入实测排名。

## 初始公平性约定

- 基准优先采用预生成 token IDs，绕开无官方 Jinja 模板的提示差异；另用经审查的本地官方消息编码做输出合理性检查。
- 筛选矩阵：短输入 512 / 输出 64，长输入 4096 / 输出 128；短输入并发 1、8、32，长输入并发1（容量和时长允许后扩展），固定 seed，ignore_eos 仅用于定长性能测量。短输出由初案128收敛为64，以控制首次筛选时长；候选另做长输出与稳态测试。
- 指标：请求/输出 token 吞吐、端到端延迟；流式服务额外 TTFT、TPOT/ITL 分布；实际 GPU 显存、启动/暖机成本；不把离线 wall time 标为 TTFT。
- 预热与计时分离，编译时间单列；各组工作负载和已运行次数明确保存。失败和未测不填 0。
- 先对核心候选使用相同长度/批量资源上限，容量优化另列；DP 方案比较全四卡聚合吞吐，不能把单副本吞吐冒充全机。
- 小样本结果用于筛选，C8N8/C32N32是单波burst而非稳态；不将少量请求的 p99 当稳定 SLA。领先方案重复至少两轮，并增加多波请求，资源/支持限制明确披露。

## 资源与复现

- 模型默认 `~/models/dsv4-flash0731`，只读使用；推理环境为项目根目录下的 `.venv-vllm/`。外部模型路径可通过 `DSV4_MODEL_PATH` 指定。
- 所有 CUDA 子进程显式设置 `CUDA_DEVICE_ORDER=PCI_BUS_ID`、`CUDA_VISIBLE_DEVICES=0,1,2,3` 或其子集；保存 UUID 映射。
- 同时只有一个研究 GPU 实验；超时仅终止本任务启动的进程组，禁止按进程名全局 kill。
- 服务若使用 HTTP，只绑定 127.0.0.1。不会修改 GPU clocks/power/驱动或其他任务。
